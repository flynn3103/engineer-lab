Engineer Lab

Learn how systems work by rebuilding them

Six interactive tours of real infrastructure. Each starts with a production problem, shows the obvious fix breaking, then reveals the design real systems use, running on your own data in the browser.

Meet the problemA concrete failure: a node dies mid-write, a 2 TB file does not fit in memory.
See the whole mapOne diagram of the system. Trace a request through it, tap any part.
Rebuild it chapter by chapterNaive attempt, real design, a playground you can break, and how you would implement it.

Apache Spark

Distributed data processing

Turn 2 TB of order logs into a revenue-per-city report by 6 AM, when no single machine can finish in time.

Partitions, lazy lineage, DAG stages, tasks and retries, shuffle, actions.

Keep accepting 30,000 orders a second while machines die and you add new ones.

Token ring, quorum, commit log and SSTables, compaction, tombstones, tablets, Raft.

Redis

In-memory data server

Answer 50,000 requests a second (sessions, counters, leaderboards, job queues) in microseconds, and recover cleanly after a crash or a failover.

Event loop, typed keyspace, expiry, eviction, AOF and RDB, replication, failover, cluster slots, streams.

Apache Kafka

Distributed event log

Fan 50,000 order events a second out to twelve teams, in order, with no loss and no duplicates when a broker fails.

Log and offsets, produce path (routing, batching, idempotence), replication and ISR, consumer groups, retention and compaction, transactions, metadata quorum.

PostgreSQL

Relational database

Take 2,000 checkout transactions a second while finance runs 10-minute reports, and never lose a committed row to a power cut.

Pages and buffer pool, executor, B-tree, MVCC, WAL and recovery, VACUUM, planner, isolation.

Container orchestration control plane

Keep 600 containers running on 120 machines through 50 deploys a day and a machine failing every other day, with no human in the loop.

API server, etcd and watches, controllers, scheduler, kubelet, services, rolling updates, autoscaling.
